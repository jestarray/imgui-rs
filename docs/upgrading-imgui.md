# Updating to new imgui versions

This document covers how to upgrade imgui-rs to a new version of the upstream C++ library.

The process is much the same to build imgui-rs for a tagged release (as shown) as it is for any arbitrary revision (such as one on a different branch)

## Summary

In short, there are a few steps:

1. Update copy of imgui itself
2. Run cimgui to generate C wrapper for imgui
3. Run bindgen
4. Fix up the imgui-rs wrapper
5. Update version in README badge (edit the URL)

## Step by step

The current sources are pinned to Dear ImGui `v1.93.0` / `v1.93.0-docking`,
cimgui `c4461a7eadbd17b6a6a8124a8abbf499aba6318d`, and bindgen `0.72.1`.
Use the same cimgui revision for all four variants. The update scripts verify it.

Generation needs LuaJIT 2.1 and a C++ preprocessor (`gcc` by default; set
`CIMGUI_COMPILER=clang` to use Clang), plus libclang for bindgen. Each script
sets `IMGUI_PATH` instead of modifying cimgui's submodule. Master variants expose
the public API; docking variants also expose internal APIs. FreeType declarations
are generated by this cimgui revision even for variants built without FreeType.

`generate-cimgui.lua` removes `[[gnu::artificial]]` from preprocessed input:
the pinned cimgui parser otherwise mistakes the new debugger attribute for a
return type. Do not edit the vendored ImGui headers to work around it.

1. Update the copies of `imgui` in `imgui-sys/third-party/imgui-*/imgui/` from the appropriate branches on [the upstream repo](https://github.com/ocornut/imgui)

    Each branch should generally be from roughly the same point in time. Generally just after each imgui release the `docking` branch is updated, so it's usually easy to find an equivalent commit in both.

    We trim some of the "unrequired" parts of imgui, such as it's `.github` directory, the `backends` and `docs`. We are mainly just interested in the main `.cpp` and `.h` files, as well as `misc/freetype/` support files.

    There's a simple shell script to perform the updates at `imgui-sys/third-party/update-imgui.sh` - this also serves as documentation of what revision was used.

2. Ensure `luajit` is installed, as this is required by cimgui's generator.

   $ luajit --help

3. Check out the `cimgui` project somewhere:

   ```sh
       git clone https://github.com/cimgui/cimgui.git /tmp/cimgui
       git -C /tmp/cimgui checkout c4461a7eadbd17b6a6a8124a8abbf499aba6318d
   ```

    When updating the generator, deliberately choose and record a new revision in
    all four scripts. Generated symbol names and C type conversions can change
    independently of Dear ImGui.

4. For each of the branches, run the corresponding `update-cimgui-output.sh` script.

   ```sh
       $ pwd
       .../imgui-sys/third-party/imgui-master
       $ ./update-cimgui-output.sh /tmp/cimgui/
       [...]
       copyfile ./output/cimgui.h ../cimgui.h
       copyfile ./output/cimgui.cpp ../cimgui.cpp
       all done!!
       $ cd ../imgui-docking/
       $ ./update-cimgui-output.sh /tmp/cimgui/
       ...
       all done!!
   ```

   This updates various files like `cimgui.cpp`, `definitions.json` and so on

   With this step, we now have new C bindings to the desired version of Dear ImGui.

5. Back in the root of the imgui-rs repo, run `cargo xtask bindgen`

    This step generates `imgui-sys/src/bindings.rs` etc which are then used by `imgui/src/*`

    ```sh
        $ cargo xtask bindgen
        Finished dev [unoptimized + debuginfo] target(s) in 0.04s
        Running `target/debug/xtask bindgen`
        Executing bindgen [output = .../imgui-rs/imgui-sys/src/bindings.rs]
        Success [output = .../imgui-rs/imgui-sys/src/bindings.rs]
        Executing bindgen [output = .../imgui-rs/imgui-sys/src/wasm_bindings.rs]
        Success [output = .../imgui-rs/imgui-sys/src/wasm_bindings.rs]
    ```

    The xtask uses its Cargo dependency on bindgen; a standalone bindgen CLI is
    not required. Set `LIBCLANG_PATH` if libclang is not on the library search
    path. All eight native/WASM files must be regenerated together. Keep the
    generation, bindgen, and C++ build defines aligned, especially
    `IMGUI_DISABLE_OBSOLETE_FUNCTIONS` and `IMGUI_USE_WCHAR32`.

6. Run `cargo build` and fix any errors caused by changes upstream (see next section)

7. Run the tests with `cargo test`.

8. Try running one of the examples in `imgui-examples` by first patching it to refer to this new imgui branch

    ```sh
        cargo run --example test_window_impl
    ```

9. Update README to reference correct Dear ImGui (updating the URL in the badge)

## Migrating applications from 1.92.9b to 1.93.0

`DrawFlags` now covers both primitive and draw-list options. `DrawListFlags` was
removed. For example:

```rust,ignore
use imgui::draw_list::DrawFlags;

// ROUND_CORNERS_BOT_LEFT becomes ROUND_BOTTOM_LEFT (and similarly for other corners).
let flags = DrawFlags::ROUND_BOTTOM_LEFT | DrawFlags::STROKE_INSIDE;
draw_list.add_rect([10.0, 10.0], [100.0, 50.0], color)
    .rounding(6.0).thickness(3.0).flags(flags).build();

// Explicitly compare with pre-1.93 drawing behavior.
draw_list.with_draw_flag(DrawFlags::STROKE_LEGACY, true, || {
    draw_list.add_line([10.0, 60.0], [100.0, 60.0], color).build();
});
```

Choose only one `STROKE_*` position; the values are encoded alternatives.
Scoped flags support anti-aliasing, legacy strokes, rounding, text pixel snapping,
and the texture/vertex-offset options, with a maximum nesting depth of three.
Other stroke positions, joins, and caps belong on individual primitives.

Drawing follows the new upstream defaults: lines no longer receive an implicit
half-pixel offset, closed shapes stroke inside their outlines, circle radii no
longer receive a half-pixel reduction, fractional filled rectangles are
anti-aliased, and inverted rectangles are invisible. Use `STROKE_LEGACY` explicitly
when migrating custom drawing that depends on the old behavior. The IO field
`config_debug_draw_list_defaults_to_stroke_legacy` enables comparison globally.

`Style::anti_aliased_lines_use_tex` was removed. Textured line rendering is now
standard and requires bilinear sampling. `anti_aliased_line_ends` enables optional
anti-aliasing at stroke ends. Replace `curve_tessellation_tol` with
`curve_tessellation_max_error`, measured in pixels:

```rust,ignore
style.curve_tessellation_max_error = old_curve_tessellation_tol.sqrt();
```

`FontAtlasFlags::NO_BAKED_LINES` now disables anti-aliased lines and line ends;
it is no longer just a texture-memory optimization. Use
`NO_BAKED_ROUND_CORNERS` to disable baked corners while keeping line textures.
Atlas texture dimensions and contents may change. External renderers must honor
texture updates and sampling requirements. No renderer backend is bundled here.

Text filters now treat spaces as AND, commas as OR, double quotes as exact
phrases, and `-term` as exclusion; exclusions always win. `draw_with_size` remains
available and delegates sizing to `SetNextItemWidth`. `draw_with_hint` returns
whether the filter changed. `ItemFlag::MIXED_VALUE` represents indeterminate
widget values; disable live editing for mixed-value text inputs when undo could
otherwise apply to all selected objects.

Dark/light themes and docking empty backgrounds adopt upstream's revised colors.
Safe font remapping is available through `FontAtlas`; loader signatures remain
available in `imgui-sys`. External and WASM providers must rebuild
against the matching 1.93.0 sources and compiler defines.

### Additional drawing and font APIs

Use `add_line_h`/`add_line_v` for pixel-aligned axis lines. Quads, n-gons,
ellipses, quadratic Béziers and concave polygon fills now have safe wrappers.
`draw_list.path()` buffers a path independently; finish it with `stroke`,
`fill_convex`, or `fill_concave`. Dropping an unfinished path draws nothing.

```rust,ignore
draw_list.add_ellipse([80.0, 80.0], [40.0, 20.0], color)
    .rotation(0.4).thickness(3.0).flags(DrawFlags::STROKE_INSIDE).build();
draw_list.path().line_to([10.0, 10.0])
    .bezier_quadratic_to([50.0, 60.0], [90.0, 10.0], 0)
    .stroke(color, 2.0, DrawFlags::CAP_ROUND);

let font = ctx.fonts().add_font(&[imgui::FontSource::DefaultFontVector { config: None }]);
ctx.fonts().remap_codepoint(font, '\u{e000}', 'A');
let ui = ctx.frame();
let _font = ui.push_font_with_size(font, 24.0);
let baked = ui.current_font_baked();
let glyph = baked.find_glyph('A'); // Owned copy, valid after further glyph loads.
ui.text("Dynamic font sizing");
```

Dynamic sizes require a backend with `BackendFlags::RENDERER_HAS_TEXTURES`.
`push_font_size` resizes the current font; zero preserves its current size.
The baked-font view is tied to the UI frame, so it cannot survive a new frame
or cache compaction. Apply remappings before baking the affected glyphs.
Raw glyph-index remapping validates the selected TrueType/OpenType source's
glyph count, rejects index zero/out-of-range values, and returns false for
unknown sources/formats. `DefaultFontBitmap` selects the fixed bitmap default.

### Core renderer integration

`TextureId::id()` now returns `u64`, matching `ImTextureID` even on WASM32.
Use `TextureId::from_u64` for graphics handles; use checked conversion if your
backend requires a narrower integer. The generic `Textures` registry starts
at one because zero is the invalid identifier for managed textures.

Before drawing, iterate `DrawData::textures()` and handle its requests:

```rust,ignore
for mut texture in draw_data.textures() {
    match texture.status() {
        imgui::TextureStatus::WantCreate => {
            let id = upload(texture.size(), texture.format(), texture.pitch(), texture.pixels())?;
            texture.mark_created(id);
        }
        imgui::TextureStatus::WantUpdates => {
            // Rectangle rows use the full texture pitch, not the rectangle width.
            upload_regions(texture.texture_id(), texture.pitch(), texture.pixels(), texture.updates())?;
            texture.mark_updated();
        }
        imgui::TextureStatus::WantDestroy => {
            destroy(texture.texture_id());
            texture.mark_destroyed();
        }
        _ => {}
    }
}
```

Leave failed requests unacknowledged to retry them. `Context::textures()` also
supports renderer shutdown; inspect reference counts when sharing atlases.
Pixel borrows cannot outlive their frame/context. `OwnedDrawData` copies CPU
pixels, update rectangles and texture references; acknowledging its snapshot
does not acknowledge requests in the source context. Copy renderer identifiers
back through the live request API if your renderer uploads from a snapshot.

Capture `ctx.platform_io().renderer_callbacks()` before `ctx.render()`.
Pure Rust backends can initialize the supported operations with
`ctx.platform_io_mut().register_renderer_callbacks(&[RendererCallback::ResetRenderState,
RendererCallback::SetSamplerLinear, RendererCallback::SetSamplerNearest])`.
Use its `classify(&command)` method to dispatch standard reset/linear/nearest/
texture-sampler commands in Rust. `draw_list.add_renderer_callback(kind)` queues
registered operations and returns false for unsupported ones. Callback pointers
are registered by backend initialization; native callbacks remain compatible
with upstream backends. Unknown application callbacks retain the existing raw
callback contract. Separate backend repositories are outside this change.

Validate default, docking, FreeType, docking+FreeType, and `tables-api`, including
the C++ ABI tests, doctests, and documentation. On Windows use
`--features freetype,imgui-sys/use-vcpkg` with an appropriate FreeType installation.
Compile-check the four WASM feature combinations separately using
`--target wasm32-unknown-unknown` (install it with `rustup target add
wasm32-unknown-unknown` before `cargo xtask test`). `--all-features` also enables
`external` and is not a native linking test.

## Common sources of problems

### Function changes

Check the upstream imgui release notes for the new versions, as they detail any breaking changes.

If functions have been renamed, the required changes to the bindings are usually simple.

If functions have been removed, the changes are usually also simple but the implications may require some thought. Note by default `cimgui` generator will exclude any obsolete API.

If new function overloads are added - for example `imgui::Thing()` existed but `imgui::Thing(float)` was added - `bindings.rs` will previously have contained only `igThing`, but will now contain `igThingNil()` and `igThingFloat(...)`

### Memory layout changes

It is common for upstream to add/remove/reorder fields, so the bindings will compile but the memory layout will not match - which will (hopefully) result in the bindings causing a segfault. These are not tagged as breaking changes in the release notes.

The `*_memory_layout` tests when running `cargo test` should catch these (if they are created for every relevant struct!)

The fix for this is usually to compare the struct in (read-only) `imgui-sys/src/bindings.rs` compared to the relevant struct in `imgui/src/...` - the ordering and data-types must match, but the names do not (structs in `imgui/src/...` should use conventional Rust naming/casing)
